# 소싱 신호 14단계 — 판정용 운영 데이터 소스 조사 및 등록일 연결

## 목적

13단계까지의 소싱 진단은 내부 주문 반응을 안전하게 요약할 수 있지만, 강한/약한 반응 상태를 확정하려면 상품이 실제로 얼마나 노출됐는지, 언제부터 테스트됐는지, 현재 판매 가능한지 같은 운영 데이터가 더 필요하다.

14단계는 먼저 **현재 OARS에서 이미 확보 가능한 데이터와 아직 없는 데이터를 분리**하고, 이미 확보 가능한 실제 상품등록일은 기존 에이블리 상품목록 파일에서 MD 시트로 안전하게 연결한다.

이번 단계에서도 추천 점수·사입 수량·자동 발주·strong/weak 활성화는 하지 않는다.

## 현재 데이터 소스 조사

### 1. 에이블리 상품목록 파일

현재 `/product-match` 화면은 에이블리 상품목록 CSV/XLSX에서 다음 필드를 읽는다.

- 상품 번호 / 상품번호
- 상품명
- 카테고리
- 상품등록일

상품목록의 `상품등록일`은 상품번호·상품명이 확실히 연결되는 경우에 한해 실제 MD의 `상품등록일` 빈칸을 채울 수 있다.

이번 단계에서 이 경로를 구현한다.

### 2. MD 시트

현재 parser가 직접 읽는 lifecycle 관련 필드는:

- 상품등록일
- 판매종료일

이다.

하지만 판매종료일이 있다는 사실만으로 현재 판매중/판매중지 상태를 확정하지 않는다.

### 3. Google 주문·클레임·재고 시트

주문 반응, 취소/반품, 재고 수량을 제공하지만 다음은 제공하지 않는다.

- 상품 노출수
- 클릭수
- 실제 노출 시작/종료
- 현재 판매중 여부

### 4. Cafe24 연결

현재 Cafe24 연결은 주문 조회/상태 변경 보조 경로다.

상품 catalog의 현재 판매 상태나 노출·클릭 지표를 OARS sourcing 진단에 공급하는 경로는 없다.

## 이번 단계에서 확보 가능한 것

### 실제 상품등록일

에이블리 상품목록 파일과 MD를 다음 순서로 검증한다.

1. productNo가 이미 있으면 productNo + 전체 상품명 일치를 확인
2. productNo가 없으면 전체 상품명 단일 일치만 허용
3. 상품목록의 상품등록일을 날짜로 검증
4. MD 카드에 `상품등록일` 라벨이 존재하는지 확인
5. 기존 MD 등록일이 비어 있을 때만 write 후보 생성
6. 미리보기 후 MD 시트 snapshot이 바뀌지 않았는지 다시 확인
7. 쓰기 후 셀을 재조회해 저장값 검증

기존 등록일은 덮어쓰지 않는다.

동일 상품번호의 상품등록일이 서로 다르면 파일 전체를 확인 대상으로 돌리고 임의 선택하지 않는다.

## 아직 확보할 수 없는 것

현재 소스만으로는 다음을 검증할 수 없다.

### 상품별 노출/클릭

상품별 노출수·클릭수 데이터 연결이 없다.

따라서 주문 0인 상품을 낮은 반응으로 판정할 수 없다.

### 실제 테스트 기간

상품등록일은 확보할 수 있지만:

`상품등록일 = 실제 노출 시작일`

로 간주하지 않는다.

판매 중지·재오픈·공지·재고/옵션 상태 등에 따라 실제 테스트 가능 기간이 다를 수 있기 때문이다.

### 현재 판매 가능 여부

판매종료일만으로 현재 판매 상태를 확정하지 않는다.

명시적인 판매상태 또는 동등한 source가 필요하다.

## 15단계 진입 조건

`evidence_strong` 또는 `weak_observed_signal`을 활성화하려면 최소한 다음 source 계약이 필요하다.

- 주문 수집 시작/완료 범위
- 상품별 현재 판매 가능 상태
- 상품별 실제 테스트 가능 기간
- 상품별 노출 데이터 또는 노출 여부를 신뢰할 수 있는 동등한 근거

현재 14단계에서 안전하게 추가 가능한 것은 상품등록일 연결까지다.

나머지 값은 현재 소스에 없으므로 추정해서 채우지 않는다.
