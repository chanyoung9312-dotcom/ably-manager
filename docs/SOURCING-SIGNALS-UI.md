# 소싱 진단 UI — 7단계 정보구조

## 목적

이 화면은 `sourcing-signals`의 관측 결과를 사람이 읽을 수 있게 보여주는 읽기 전용 화면이다. 추천 점수, 순위, 사입 수량, 자동 소싱 행동은 만들지 않는다.

데이터 흐름은 고정 fixture가 아니라 운영 데이터의 다음 경로를 사용한다.

`Google Sheets → buildCommerce/loadDashboard → sourcing taxonomy → sourcing-signals → sourcing view model → /sourcing UI`

## 첫 화면

상단에는 분석 상품, 주문 연결 상품, 주문 반응 상품, 최근 30일 활성 상품만 보여준다. 142개 그룹은 서로 겹치므로 그룹 수를 상품 수처럼 합산하지 않는다.

카드는 기본 18개만 노출하고, 최근 30일 활성 상품 수를 우선으로 정렬한다. 사용자는 품목/디자인/핏·실루엣/소재 표현/패턴/기장/조합 필터와 상태 필터를 사용할 수 있다. 추천순 정렬은 없다.

## 카드

카드는 그룹명, 그룹 종류, 주 상태, 핵심 근거 3개, 템플릿 설명, 최근 관측 문장, 중요한 플래그를 먼저 보여준다. 주문 수집 완전성·노출수·테스트 기간이 모두 확인되지 않은 현재 운영 데이터에서는 화면 상단에 관측 한계 문구를 고정 노출한다.

주 상태의 사용자 문구는 다음과 같다.

- `exploration_signal` → 탐색 신호
- `concentration_dependent` → 특정 상품 의존
- `insufficient_data` → 판단 자료 부족

`evidence_strong`과 `weak_observed_signal`은 6단계 정책에서 비활성화 상태를 유지한다.

## 상세

자세히 보기에는 확산성, 반복성, 30/14/7일 최근성, TOP1/2/3 집중도, 데이터 상태를 한국어 용어로 보여준다. 내부 기호인 DE/DN이나 reasonCode 원문은 노출하지 않는다. null은 0으로 치환하지 않고 "확인 필요"로 표시한다.

## 중복 근거

동일한 `memberKeys`를 가진 그룹은 하나의 대표 카드로 묶는다. 대표 우선순위는 baseType → secondaryCategory → primaryCategory → attribute → combination 순이다. 숨긴 그룹은 "동일 상품 집합"으로 표시한다.

한 상품이 여러 속성의 근거가 되면 `sharedEvidence`를 이용해 "근거 상품 공유"를 표시한다. 이 표시는 여러 속성을 독립 성공 사례처럼 해석하지 않도록 하기 위한 것이다.

## 데이터 부족

주문 0은 실패나 비추천으로 표현하지 않는다. 노출과 테스트 기간이 없는 경우 "판단 자료 부족"으로 설명한다. L=0인 그룹은 해당 카드만 계산 보류로 표시하고 다른 카드까지 실패시키지 않는다. eligibleQty(E)는 추천 사입 수량이 아니므로 사용자 문구는 "판단 반영 수량"으로 표시한다.

## 반응형

PC에서는 2~3열 카드, 모바일에서는 1열 카드를 사용한다. 긴 표와 가로 스크롤 대신 카드 상세 영역 안에서 지표를 세로로 읽도록 구성한다.
