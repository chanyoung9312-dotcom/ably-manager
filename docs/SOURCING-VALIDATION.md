# 소싱 신호 15단계 — 검증된 강한 근거 상태 활성화

## 목적

6단계의 관측 엔진에는 이미 `evidence_strong` 승격용 게이트가 계산되어 있었지만, 정책상 상태 자체는 비활성화되어 있었다.

15단계에서는 **기존 관측 계산을 바꾸지 않고**, 별도 검증 레이어에서 충분한 운영 데이터가 확인된 그룹만 `강한 근거`로 표시할 수 있게 한다.

현재 운영 데이터는 상품별 노출·실제 테스트 기간·현재 판매 가능 여부가 아직 확인되지 않으므로, 실제 live snapshot에서는 강한 근거 승격이 발생하지 않는다.

## 강한 근거 승격 조건

다음 조건을 모두 만족해야 한다.

1. 기존 관측 상태가 `exploration_signal`
2. 그룹 `validationStatus === validated`
3. 기존 sourcing-signals가 계산한 strong gate가 모두 true

기존 strong gate:

- 연결 상품 표본
- 반응 상품 수
- 다른 날짜 반복 / 순판매 반복 / 판단 반영 반복
- 최근30일 반복
- 최근14일 판단 반영 상품
- TOP1/TOP2 제거 후 잔존 반복
- 최근 지표 일관성
- 주문 수집 범위
- 판매 가능 상태
- taxonomy 확인
- 수량 사실 완전성

숫자 기준은 새로 만들지 않고 기존 stage5~6 정책을 그대로 사용한다.

## 관측 엔진과 분리

새 모듈:

`lib/sourcing-validation.mjs`

이 모듈은 기존 diagnostics를 입력받아:

- `observedState`
- `resolvedState`
- strong 승격 여부
- 미충족 strong gate

만 계산한다.

다음은 변경하지 않는다.

- Q/C/N/E
- 반복 상품 계산
- 집중도 계산
- candidate lane
- 사입 수량
- taxonomy

## weak_observed_signal

`weak_observed_signal`은 이번 단계에서도 활성화하지 않는다.

이유:

충분한 노출·테스트를 받은 모집단에서 무엇을 “약한 반응”으로 정의할지 사전 기준이 아직 없다.

예를 들어 다음 중 어느 기준을 사용할지 현재 데이터만으로 정할 수 없다.

- 최소 노출수
- 최소 클릭수
- 최소 테스트 일수
- 상품별 판매 가능 일수
- 노출 대비 주문 전환

따라서 weak 상태를 임의 기준으로 활성화하지 않는다.

정책에서 weak 활성화를 요청하면 `WEAK_PROTOCOL_NOT_DEFINED`로 거부한다.

## UI

`buildSourcingView`는 검증 레이어 결과가 있을 때만 `강한 근거` 상태를 표시한다.

검증 레이어가 없거나 승격 조건이 충족되지 않으면 기존:

- 탐색 신호
- 특정 상품 의존
- 판단 자료 부족

상태를 그대로 유지한다.

후보 엔진과 소싱 검토 브리프는 관측 상태를 계속 사용하므로 이번 단계에서 추천 후보 수가 변하지 않는다.

## 현재 운영 결과

현재 live 데이터에는 상품별:

- 노출 확인
- 실제 테스트 기간
- 현재 판매 가능 여부

가 없으므로 `validationStatus=validated` 조건을 충족할 수 없다.

따라서 현재 화면에서 `강한 근거`가 0개인 것은 정상이다.

상품등록일이 채워져도 이를 노출 시작일 또는 실제 테스트 기간으로 대체하지 않는다.
