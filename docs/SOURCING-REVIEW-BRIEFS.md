# 소싱 신호 13단계 — 소싱 검토 브리프

## 목적

12단계까지는 품목 후보, 조합 근거, 실제 기여 상품까지 확인할 수 있다.

13단계는 이 정보를 한 화면에서 다시 읽기 쉽게 묶어 **“이번에 무엇을 검토해야 하는가”**를 사람이 빠르게 확인할 수 있는 읽기 전용 브리프로 만든다.

이 브리프는 추천 점수, 추천 순위, 사입 수량, 자동 발주를 만들지 않는다.

## 대상

브리프 대상은 10단계 후보 엔진의 `review_candidate`만이다.

- `hit_reference`
- `emerging_watch`
- `data_hold`

는 브리프에 승격하지 않는다.

현재 검증 snapshot에서는 숏·하프팬츠가 대상이다.

## 브리프 구성

각 브리프는 다음을 보여준다.

- 품목명
- 연결 상품 수
- 반응 상품 수
- 다른 날짜 반복 상품 수
- 최근30일 활성 상품 수
- TOP2 주문 비중
- 품목 수준 관측 요약
- 조합 수준 근거 단계
- 대표 근거 상품 최대 3개
- 주의 플래그

## 조합 근거

조합은 기존 상태를 그대로 나눈다.

- `supported_hint` → 반복 근거 확인
- `emerging_hint` → 초기 관측
- `concentrated_hint` → 특정 상품 의존
- `data_hold_hint` → 데이터 보류

브리프에서 `supported_hint`가 없으면 **“품목 후보는 성립하지만 반복 근거가 확인된 조합은 아직 없음”**이라고 명시한다.

따라서 숏·하프팬츠가 review candidate라도 `숏·하프팬츠 ∩ 데님`이 emerging hint라면 “데님을 소싱하라”로 바꾸지 않는다.

## 대표 근거 상품

12단계 evidence에서 주문 반응이 큰 상품 최대 3개를 참고용으로 표시한다.

이 목록은:

- 상품 추천 순위가 아니다.
- 재주문 목록이 아니다.
- 신규 소싱 상품과 동일하게 복제하라는 의미가 아니다.

기존 반응 구조를 빠르게 확인하기 위한 참고 자료다.

## 외부 수요

13단계는 외부 검색량, 플랫폼 트렌드, 시장 수요를 추정하지 않는다.

따라서 현재 브리프는 내부 관측 데이터만 설명한다.

향후 외부 수요 데이터를 연결하려면 별도 출처와 별도 검증 계약이 필요하다.

## 데이터 흐름

`sourcing-signals → sourcing-candidates → sourcing-evidence → sourcing-briefs → sourcing-brief-view → /api/sourcing-signals → /sourcing`

## 금지 사항

- 추천 점수
- 추천 순위
- BEST
- 사입 수량
- 자동 발주
- 외부 수요 추정
- 초기 조합을 반복 근거로 승격
- hit reference를 review candidate로 승격
- candidate lane 재계산
