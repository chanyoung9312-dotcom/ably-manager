# 소싱 신호 11단계 — 소싱 검토 후보 UI 연결

## 목적

10단계 `sourcing-candidates` 엔진을 실제 `/sourcing` 화면에 연결한다.

이 화면은 추천 랭킹이나 사입 지시 화면이 아니다. 기존 관측 데이터를 다음 네 분류로 읽기 쉽게 묶는 것이 목적이다.

- 소싱 검토 후보
- 히트 구조 참고
- 추가 관찰
- 데이터 보류

## 데이터 흐름

`loadDashboard → sourcing-live → sourcing-signals → sourcing-candidates → sourcing-candidate-view → /api/sourcing-signals → /sourcing`

운영 UI는 fixture를 직접 읽지 않는다.

## 후보 화면

기존 판정 준비 상태 아래에 `소싱 검토 분류` 영역을 추가한다.

각 품목 카드에는 다음만 표시한다.

- 품목명
- 분류명
- 연결 상품 / 반응 상품
- 다른 날짜 반복 상품
- 최근 30일 활성 상품
- TOP2 주문 비중
- 규칙 기반 관측 설명
- 중요한 주의 플래그
- 동일 상품 집합 alias
- 해당 품목 안의 combination 관측

후보 내부 정렬은 최근 30일 활성 상품 수 → 다른 날짜 반복 상품 수 → 반응 상품 수 → 이름 순으로만 처리한다. 숫자 순위나 점수는 만들지 않는다.

## 분류 의미

### 소싱 검토 후보

여러 상품에서 반응이 확인되고, 다른 날짜 반복과 최근 30일 활동이 함께 관측된 품목.

구매/사입 지시가 아니다.

### 히트 구조 참고

반응은 있으나 특정 상품 의존이 큰 품목.

누적 판매량을 품목 전체의 성과로 일반화하지 않는다.

### 추가 관찰

반응은 있으나 반복성 또는 최근 근거가 아직 제한적인 품목.

### 데이터 보류

현재 자료로 후보 여부를 구분하기 어려운 품목.

주문 0을 실패로 표현하지 않는다.

## 속성/조합

단일 attribute는 독립 후보 카드로 표시하지 않는다.

combination은 품목 카드 안의 관측 힌트로만 보여준다.

- 반복 관측
- 초기 관측
- 특정 상품 근거
- 데이터 보류

shared evidence가 있으면 `근거 상품 공유`를 표시한다.

## 기존 진단 유지

후보 분류 아래에는 기존 `세부 진단 보기`를 그대로 유지한다.

따라서 사용자는:

1. 품목 단위 검토 분류를 먼저 보고
2. 필요하면 품목·속성·조합의 전체 진단 카드에서 세부 근거를 확인할 수 있다.

## 금지 사항

이번 단계에서도 다음은 추가하지 않는다.

- 추천 점수
- 1위/2위 같은 추천 순위
- BEST
- 사입 수량
- 자동 발주
- 소싱 확대/축소 행동
- strong/weak 상태 활성화
